# DRUID

**D**epth-**R**esolved **U**–Pb **I**sotope **D**ata reduction
—— LA-ICP-MS 锆石 U-Pb 定年数据还原工具

把 Qtegra/iCAP 导出的原始计数率（cps）时间序列，还原成**带不确定度的年龄**、
**标样质控表**与**逐深度的年龄剖面**；其中逐窗口剖面可以直接交给
[ADEPT](../ADEPT) 做坪年龄与 MSWD 判定。

名字取 "Depth-Resolved" 不是修辞：本工具与只做整段积分的常规流程最大的区别，
是它把每个测点当成一条**随时间（即随坑深）变化的信号**来处理——分馏按深度校正、
年龄域按深度划分。ADEPT 负责在这条剖面之上挑坪，两者是同一条链的两端。

```
Qtegra CSV (cps)
   │
   ├─ DRUID ────────────────────────────────────────────┐
   │   剥蚀区间识别 → 扣空白 → Hg干扰/普通铅校正        │
   │   → 标样夹逼归一化 + F(τ) 深度分馏校正             │
   │   → 整段年龄 + 逐窗口年龄剖面（含 1σ）             │
   │                                                    ▼
   └─ 结果.xlsx  ──[剖面窗口] 表──▶  ADEPT  ──▶  坪年龄 + MSWD
```

## 一、安装与运行

三种用法，按熟悉程度选。

### 1. 网页界面（推荐，不需要命令行）

双击 **`启动数据处理工具.bat`**，浏览器会自动打开。之后全程在网页上点：
选文件夹 → 看检查报告 → 开始处理 → 下载结果。关闭黑窗口即退出。

### 2. 命令行（批处理、脚本化）

```bat
python -m druid.cli.reduce_batch ^
    --dir "G:\1.云龙锡矿\云龙锡矿锆石\20220301CKDB" ^
    --out "结果\20220301CKDB_U-Pb结果.xlsx" ^
    --plot
```

### 3. 作为库调用

```python
from druid import __version__
from druid.workflow import BatchConfig, run_batch
from druid.io.report import export_batch

cfg = BatchConfig(data_dir=r"G:\...\20220301CKDB")
result = run_batch(cfg)
export_batch(cfg, result, version=__version__)

result.results   # 逐点结果表
result.qc        # 标样 QC 表
result.windows   # 逐窗口年龄剖面（供 ADEPT 使用）
```

### 可选：注册成命令

```bat
pip install -e .
druid-reduce --dir 某批次目录 --plot
druid-gui
```

装与不装都能用；不装时在包根目录（含 `druid/` 的那一层）跑
`python -m druid.cli.xxx` 即可。

### 自检：确认它没坏

改过任何东西、或者换了一台机器之后跑一下：

```bat
python tests\run_all.py
```

不需要装 pytest。装了开发依赖（`pip install -e ".[dev]"`）的话，
`python -m pytest -q` 是等价且报告更清楚的一条路——CI 用的是这条。

自检覆盖三层：统计内核（卡方上尾概率、加权平均、MAD 判离群，参考值取自 R）、
输入边界（Qtegra CSV 解析、剥蚀区间、气体空白、窗口切分，用合成数据）、
打包（版本号一致、入口点可调用、网页资源齐全）。**不含**真实批次的端到端数值
比对——那需要数据，只能人工做，做法见 `AGENTS.md` §4。

**依赖**：`numpy` `pandas` `matplotlib` `openpyxl` `xlrd`。
不需要 `scipy`——年龄方程的不动点迭代与二分法都是自己实现的。
网页界面只用标准库（`http.server`），无额外依赖、无 npm、无构建步骤。

## 二、输入数据要长什么样

一个批次放在一个文件夹里，文件夹名即批次名：

```
20220301CKDB\
    20220301CKDB_LIST.xls     ← 测点序列表：第 1 列文件名，第 2 列样品名
    20220301CKDB_1.csv        ← 每个测点一个 Qtegra 导出的 CSV
    20220301CKDB_2.csv
    ...
```

要点：

- 序列表必须叫 `<目录名>_LIST.xls` 或 `.xlsx`（也接受 `.xlsm` / 小写）；
- LIST 里登记的文件名**不带 `.csv` 后缀**（Qtegra 导出的默认格式）；
- 样品名决定角色，识别规则见下表；
- 每个 CSV 必须含 202 / 204 / 206 / 207 / 208 / 232 / 238 全部通道。

| 样品名里出现 | 判定为 | 在流程里的作用 |
|---|---|---|
| 参数 `--primary`（默认 `91500`） | 主标 | 算归一化因子 F，**决定绝对年龄是否成立** |
| 参数 `--secondary`（默认 `Ple`） | 监控标样 | 估外部重现性 σ<sub>ext</sub>、QC、二次校正 |
| `SRM` / `NIST` / `612` / `610` | 玻璃标样 | 不参与 U-Pb（给它定年没有意义） |
| 其余 | 未知样品 | 真正要定年的对象 |

网页界面会先做一次检查，缺文件、缺序列表当场告诉你，不必等跑完。

**纯标样批次**（只有 91500 没有未知样品）也能处理：只输出标样 QC，
深度域判别与二次校正自动跳过。

**没有主标的批次**不会崩，而是退化为「未校准 / 原始比值」诊断模式，
并在结果表里标注 `校准状态 = 未校准`——这种年龄**只能作相对参考，不可用于定年**。

## 三、它做了什么

十步流水线，每一步都能在结果表的「运行参数」里追溯到所用参数。

| 步 | 做什么 | 关键点 |
|---|---|---|
| ① | 读序列 LIST | 文件名 → 角色 |
| ② | 逐点装载 + 整段还原 | 读 CSV → 死时间 → 找剥蚀段 → 扣空白 → 裁边；单点失败不影响整批 |
| ③ | 主标建立深度剖面 | 供 F(τ) 使用 |
| ④ | 构造夹逼关系 | 每个测点取前后各一个最近的主标 |
| ⑤ | 算两套整段比值 | `simple`（单一因子）与 `ftau`（逐窗口 F(τ) 后按计数合成） |
| ⑥ | 主标归一化因子 F | **沿序号线性插值**，不是全程常数；MAD 稳健剔除离群主标 |
| ⑦ | 估计外部重现性 | 由监控标样散度扣除内部精度得到 σ<sub>ext</sub> |
| ⑧ | 逐点年龄与不确定度 | 三个体系（206/238、207/235、207/206）+ 协和度 |
| ⑨ | 深度剖面年龄域判别 | 滑动窗口 → BIC 分割 → 边界精修 → 合并伪分域 |
| ⑩ | 标样 QC + 二次校正 | 加权平均 + MSWD；用监控标样做基体匹配再校准 |

### 三条不要轻易改动的设计

**1. 204 普通铅校正必须做显著性检验。**
204Pb 通常只有几~几十 cps，而 204Hg 本底可达数百 cps，两者做差之后残余往往
就是噪声。若 204Pb 不显著却强行扣除，等于把噪声当普通铅扣掉——对计数本来就
很少的 207Pb 是灾难性的。

**2. 207Pb/206Pb 不做 F(τ) 逐窗口深度校正。**
它是 Pb 同位素比值，几乎不随坑深分馏（随坑深漂移的是 Pb/U 这类元素对比值）；
而窗口级 207Pb 计数极少（4 s 窗口仅约 130 个计数），套 F(τ) 只会注入噪声。
它仍然参与**归一化**（F76），只是不做逐深度校正。

**3. 剥蚀区间用两级阈值，以峰值比例阈值为主。**
只用「本底 + kσ」会把 washout 拖尾一起算进来（关激光后 10 s 仍有 100~200 cps），
把大量零信号混入积分窗口。

## 四、输出怎么读

结果 Excel 有五个工作表：

| 表名 | 内容 |
|---|---|
| `结果` | 每行一个测点：U/Th 计数率、三种年龄与不确定度、协和度、深度结构 |
| `标样QC` | 主标与监控标样的加权平均年龄、MSWD、与推荐值的偏差 |
| `深度剖面域` | 检出多个年龄域的测点，逐个域列出归一化深度 τ、年龄与 **MSWD** |
| `剖面窗口` | **逐窗口年龄剖面，列名按 ADEPT 的输入约定对齐**（见下节） |
| `运行参数` | 本次运行的全部参数与被跳过的文件，便于半年后回溯 |

**先看三个数判断数据能不能用**：

1. `标样QC` 里 91500 的偏差 —— 绝对值应小于 1%；
2. 监控标样 Ple 的偏差 —— 绝对值应小于 3%；
3. 协和度落在 90–110% 的样品占比 —— 应大于 85%。

三项都过，数据可用。

### `深度剖面域` 那一列 MSWD 怎么看

`年龄_Ma` **本身就是反比方差加权平均**（不是算术平均），`MSWD` 与
`MSWD_概率` 都在这个加权口径上算，与 R 端 ADEPT 的 `MSWD` / `MSWD probability`
完全同口径，两边可以直接对照：

```
MSWD ≈ 1        该域的散布与各自的不确定度相符 → 一个年龄能解释它
MSWD ≫ 1        要么真的有多个年龄混在里面，要么 σ 被低估
                （最常见的原因：只算了计数统计，没算外部重现性）
MSWD ≪ 1        σ 被高估了
MSWD_概率       零假设（该域只有一个年龄）下，MSWD 至少这么大的概率。
                小于约 0.05 是常规的"不自洽"警戒线。
```

注意 `n_win` 只统计**有效**窗口（σ 缺失或非正的窗口被排除），所以它可能小于
`i1 - i0`；MSWD 的自由度是 `n_win − 1`。

不确定度列里，`s68_1sig` / `s68_2sig` 分别是 **1σ 与 2σ**，别拿错——
下游算 MSWD 必须用 **1σ**，用 2σ 会把 MSWD 缩小到四分之一。

`年龄207_235` 的不确定度是**近似**传播的（把 206Pb/238U 的相对不确定度原样搬过来），
不是从两个比值的协方差严格算出来的。口径自 1.x 起未变，以保证已发表数字可比。

> 两个工具为什么分开、数据在它们之间如何变化、边界上到底传了什么，
> 见 **[docs/druid-adept-dataflow.html](docs/druid-adept-dataflow.html)**
> （单文件自包含，含流程图与真实数据图，可直接用浏览器打开）。

## 五、与 ADEPT 的接口

这是本工具存在的意义之一：把「原始信号」与「坪年龄判定」之间的那段路修通，
让 ADEPT 不必也不该去碰 cps。

### 为什么不由 ADEPT 从 cps 做起

从 cps 到一个可靠的比值，中间有七步：死时间校正、204Hg 干扰、普通铅显著性检验、
普通铅校正、标样夹逼、F(τ) 分馏校正、jackknife 不确定度。这些都在 DRUID 里。
而且从 cps 逐点推 σ 在物理上就不成立：单 cycle 的 207Pb 只有几十个计数，
真实噪声以闪烁噪声为主而非泊松噪声；cps 本身还已经除过积分时间、做过死时间校正。

### 接口契约

`剖面窗口` 表的列：

| 列 | 含义 |
|---|---|
| `Analysis` | `序号 样品名`，作为分组键 |
| `Time` | 窗口中心时刻 (s) |
| `Age68` | 窗口 206Pb/238U 年龄 (Ma) |
| `Age68_1s` | 该年龄的 **1σ** (Ma)，已含内部 jackknife + 外部重现性 |
| `Tau` / `R68` / `s68` / `ThU` / `U_cps` / `f206_pct` / `n_cycles` | 诊断用 |

```r
adept("20220301CKDB_U-Pb结果.xlsx",
      lower_ablation_time    = 0,      # DRUID 已切好自己的剥蚀窗口
      upper_ablation_time    = 1e6,    # 上界放到最后一个窗口之后
      smooth                 = "none", # 关键：数据已做 F(τ) 校正，剖面本就是平的
      calibration_uncertainty = 0)     # 关键：σ 已含外部重现性，再乘 3% 就重复计入
```

ADEPT 会读 `剖面窗口` 表，忽略同一工作簿里其他不含 `Age68` 的表；
它用反比方差加权平均给出坪年龄，并报出 MSWD 与「散度与给定误差是否自洽」的概率。

**三个参数为什么必须显式给**：ADEPT 不去猜数据是否已经预处理过——
一个 `_1s` 列说明不了剥蚀窗口在哪里结束。猜错了会静默改变进入分段的数据点数。

## 六、代码结构

```
druid/
  core/        纯计算：衰变常数、标准物质库、年龄方程、普通铅、统计 —— 无 I/O、可单独测试
  io/          读写：Qtegra CSV 解析、序列 LIST、Excel 报表
  reduction/   单点还原：装载流程、剥蚀段识别、同位素比值与 jackknife 不确定度
  depth/       深度剖面：滑窗、F(τ) 分馏校正、BIC 年龄域判别、出图
  webui/       网页界面：任务管理 / 业务层 / HTTP 服务 / 静态页面
  cli/         命令行入口：reduce_batch（批处理）、serve_ui（网页界面）
  workflow.py  编排层：BatchConfig 集中所有可调参数，run_batch 串起十步
```

分层原则：**core 不 import io，io 不 import reduction**，依赖只朝一个方向。
想改算法去 `core` 或 `reduction`；想改流程顺序去 `workflow`；
想加界面控件改 `webui/static/`，业务逻辑在 `webui/handlers.py`。

**所有可调参数的默认值集中在 `workflow.py` 的 `BatchConfig`**，
改默认值只改那一处。命令行参数只是把 argv 翻译成 `BatchConfig`。

### 数据结构的唯一契约

一个测点用一个 `Tra` dataclass 表示（`reduction/trace.py`）：原始信号、净信号、
时间轴、剥蚀区间坐标、样品名与角色都在里面。用 dataclass 而不是长元组，
是为了加字段时不必去改所有调用点。

### 物理常量只允许出现一次

`core/constants.py` 是全部数值常量的唯一出处。同一个衰变常数在两处各写一遍，
迟早会改了一处忘了另一处——而这种错误在同位素年代学里不报错，只是悄悄给出
错误的年龄。

## 七、已知限制

- **标样与样品计数率相差一个数量级时**（本项目：91500 约 1×10⁵ cps，云龙锆石约
  1×10⁶ cps），单一线性归一化因子无法完全消除高计数率下的非线性残差，表现为
  监控标样系统性偏老。第 ⑩ 步的二次校正是**基体匹配**的治标办法；
  正式发表前应尽量缩小信号强度差距（换小束斑 / 调低能量），或施加可靠的死时间校正。
- **网页界面没有「停止」按钮**，这是刻意的：Python 线程无法安全地强制终止，
  做了按钮就会变成「点了没反应」。批处理通常两三分钟，等它跑完即可；
  实在要中止就关掉黑窗口（服务端任务会继续跑完并写盘）。
  服务只监听本机回环地址，**不要改成 `0.0.0.0`**。
- **`--deadtime-ns` 默认为 0**（不校正）。需要时应由标样计数率扫描实验标定，
  不要凭经验填。本实验室实测值 `14.7645` ns 记在 `druid/deadtime_ns.txt`，
  但**没有任何代码会自动读它**——要用请显式传 `--deadtime-ns 14.7645`。
  之所以不做成默认值：一旦默认开启，历史上所有未校正的结果就不再可比。
