DRUID 与 ADEPT：一个剥蚀坑里的两个问题

两个工具为什么分开、数据在它们之间如何变化、边界上到底传了什么

一句话：DRUID 负责「测出来」，ADEPT 负责「读出来」。

DRUID 把原始计数率变成随深度变化的年龄（每个深度上的年龄是多少、误差多大）； ADEPT 在同一条随深度变化的年龄上认出哪些区间构成真实的、内部自洽的年龄域。

前者是测量问题，后者是判读问题。分开不是设计癖好，是因为它们需要的东西完全不同—— 一个需要标样、干扰校正和分馏校正，另一个需要的是分段判据与地质上的取舍规则。

一、问题的来源在样品里，不在软件里

一次激光剥蚀在锆石上打出一个约 20–40 μm 深的坑。锆石在坑的深度方向上是分层的： 继承核、变质增生边、岩浆环带，年龄可以相差几百个百万年。也就是说， 同一束激光在同一个点上，浅处和深处打到的其实是不同时代的东西。

常规做法是把整个剥蚀段积分成一个数。这在单年龄的样品上没问题， 在分层的锆石上则会把几个不同的年龄搅在一起——得到的既不是核的年龄，也不是边的年龄， 而是一个没有任何地质含义的混合值。

这不是假想的风险，本批次里就有。测点 S02 整段积分给出 436.5 Ma、协和度 51.7%——协和度这么低的"年龄"是不能用的。但它的浅部深度域 给出 440.4 Ma，是干净的结果。整段平均把这个点的可用信息直接抹掉了。

于是分裂出两个必须分开回答的问题：

① 每一深度上，年龄是多少、误差多大？

这是测量问题。要回答它，需要标样夹逼归一化、204Hg 干扰校正、 普通铅显著性检验、随坑深变化的分馏校正、以及逐窗口的不确定度传播。 这是 DRUID 的工作。

② 这些深度里，哪些区间构成一个真实的年龄域？

这是判读问题。要回答它，需要分段、需要"一个坪至少要多长"、 需要"坪内方差多大算合格"、需要"年龄随深度该朝哪个方向变"。 这是 ADEPT 的工作。

两个问题对应两种错误，而且它们不能互相检查：测量错了（例如标样归一化有偏）， 判读得再对也是错的年龄；判读错了（例如把两个混合窗口当成一个坪）， 测量再准也得到假的坪。分开做，两边的错误才各自可查。

三、边界上传来什么

DRUID 交出的那张表

DRUID 的结果工作簿有五个工作表，其中只有一张是给机器读的： 「剖面窗口」。它的列名就是按 ADEPT 的输入约定取的，所以不需要改列名、不需要转录。

列含义用途
Analysis「序号 样品名」，如 07 S01ADEPT 用它分组，一个值 = 一个测点
Time窗口中心时刻 (s)横轴，等价于坑深
Age68窗口 206Pb/238U 年龄 (Ma)ADEPT 分段的输入
Age68_1s该年龄的 1σ (Ma)ADEPT 算 MSWD 的输入
Tau归一化剥蚀进度（0→1）诊断、画图
R68 / s68比值与其相对不确定度诊断
ThU / U_cps / f206_pctTh/U、238U 信号强度、普通铅占比诊断：判断这个窗口可不可信
n_cycles该窗口里累计了几个 cycle诊断

为什么这些诊断列要一起带过去？因为它们让"这个坪为什么被丢掉"这件事可以事后复核。 只有 Age68 和 Age68_1s 两列也能跑，但一旦某个坪被过滤掉， 你就只能看到"少了一个",看不到"少了的原因是不是 f206 在那一窗突然升高"。

ADEPT 这边必须显式给的四个参数

ADEPT 刻意不去猜数据是否已经预处理过。一个 _1s 列说明不了剥蚀窗口在哪里结束， 也说明不了 σ 里包含了哪些项，所以这些必须由调用方声明：

adept("EX2022A_U-Pb结果.xlsx",
      lower_ablation_time    = 0,       # DRUID 已经切好了自己的剥蚀窗口
      upper_ablation_time    = 1e6,     # 上界放到最后一个窗口之后
      smooth                 = "none",  # 数据已做 F(τ) 校正，剖面本就是平的
      calibration_uncertainty = 0)      # σ 已含外部重现性，再乘 3% 就重复计入
参数取值设错的后果
lower/upper_ablation_time0 / 1e6 ADEPT 默认按 29–58 s 切窗口，而 DRUID 的窗口时刻是 29.97–67.47 s。 用默认值会静默截掉尾部 9 个窗口——数据少了一截，不报错，只是年龄变了。
smooth"none" DRUID 已经做过逐深度分馏校正，剖面在域内本来就是平的。 再用 LOESS 平滑，会把真实的域边界一起抹平——边界正是要找的东西。
calibration_uncertainty0 DRUID 的 σ 已含标样外部重现性。再乘 3% 就是把它算两遍： 坪的不确定度会从 1.8 Ma 变成 13.7 Ma，差一个数量级。

为什么不让 ADEPT 直接从 cps 做起

这是最先要排除的方案，因为它看起来最"省事"。

算法上，从 cps 到一个可靠的比值中间有七步：死时间校正、204Hg 干扰、 204Pb 显著性检验、普通铅校正、标样夹逼归一化、F(τ) 分馏校正、jackknife 不确定度。 这七步全在 DRUID 里，而且其中标样夹逼需要整批数据（前后主标）， 单个测点根本算不出来——ADEPT 拿到一个孤立的点，F(τ) 无从构造。

物理上，从 cps 逐点推 σ 也不成立：一个 cycle 的 207Pb 只有几十个计数， 真实噪声以闪烁噪声为主而非泊松噪声；而且 cps 本身已经除过积分时间、做过死时间校正， 再套一次泊松公式是把错误的模型用在已经处理过的量上。

所以正确的分工不是"ADEPT 做得少"，而是"ADEPT 做的事要在正确的层级上做"。 测量层级归 DRUID，判读层级归 ADEPT。

五、"两边都能分域"这件事怎么理解

这里必须说清楚，否则确实会让人觉得奇怪：DRUID 自己也会分割深度剖面 （depth/domains.py，BIC 二分），ADEPT 也做分段（PELT + 四步过滤）。 这不是隐藏的重叠，是真实存在的重叠。它成立于三个理由：

1. 判据不同，问的问题也不同

DRUID 的分域是诊断：目的是判定"这个测点到底是均一还是多域"， 并顺便为 F(τ) 找出该用哪些窗口、把混合窗口剥掉。它的输出是一个标签 （均一 / 多域(3)）和一张粗略的域明细表， 服务于"这个点能不能用"这个判断。

ADEPT 的分段是产出：目的是给出可直接写进补充材料的坪年龄表。 它的四步过滤（年龄范围、坪内方差、最短坪长、年龄随深度的单调方向） 是地质上"什么算一个坪"的判据，再配上参数敏感性扫描——这些 DRUID 不做，也不打算做。

2. 两者的结论应当一致，不一致本身就是信号

在同一个测点上，如果 DRUID 说"多域(3)"而 ADEPT 只给出 1 个坪， 说明有 2 个域被 ADEPT 的判据挡掉了——可能是坪太短，也可能是方差超限。 这不是矛盾，而是一个值得看一眼的提示：要么参数选得太严，要么那两个域本来就不该报。 上面那幅图里，中间约 490 Ma 的段落就属于这种情况。

3. 但不要拿两套数字写文章

同一个测点从两个工具各得到一个年龄，看起来可以互相印证， 但写进文章时必须只选一套口径。混用会让审稿人无法判断你的数字是怎么来的。

建议以 ADEPT 的输出为准：它是 Wang et al. (2026) 那篇方法文章的实现， 审稿人认这个口径，而且它给出了完整的不确定度预算（随机 / 系统 / 衰变常数三项分开） 和可直接引用的 MSWD。DRUID 的域表只作诊断用。

六、三个容易做错的地方

① _1s 是 1σ，不是 2σ

DRUID 的结果表里 s68_1sig 与 s68_2sig 是并列的两列。 拿 2σ 那一列去做 ADEPT 的输入，MSWD 会缩小到四分之一—— 一个本该被判定为"不自洽"的坪，会看起来完全没问题。这是最危险的一种错误：不报错，只是结论反了。

② 已校正的数据不要再平滑

DRUID 的 F(τ) 校正就是为了让域内的剖面变平。 再套一次 LOESS，会把真实的域边界一起抹平——边界恰恰是要找的东西。

③ 外部重现性不要计两次

DRUID 的 σ 构成是 sqrt(内部 jackknife² + (外部重现性 × 比值)²)， 已经包含了标样散度。ADEPT 的 calibration_uncertainty 默认再乘 3%， 所以接 DRUID 的数据时必须置 0。不置零的后果是量级级别的：1.8 Ma → 13.7 Ma。

八、什么时候只需要其中一个

  • 只拿到原始 CSV → 必须先跑 DRUID。ADEPT 可选：如果只关心整段年龄， DRUID 的结果表就够了；如果要坪年龄和 MSWD，再接 ADEPT。
  • 只拿到别人给的年龄剖面（没有 cps，例如合作者发来的 Excel）→ 只需 ADEPT。 只要表里有 Analysis / Time / Age68 / Age68_1s， 格式就是兼容的；没有 σ 列也能跑，只是不报 MSWD。
  • 数据已发表、只想复核坪 → 只需 ADEPT。把当时的年龄序列喂回去， 看 MSWD 与坪的划分是否复现。
  • 要出整段的元素含量、Th/U 趋势 → 只需 DRUID，这与 ADEPT 无关。

也就是说 ADEPT 并不依赖 DRUID。DRUID 是这条链在自己实验室里的前端， 而不是 ADEPT 的前置条件——这一点让两个工具各自独立可用， 也正是它们能互为验证的原因。

# ① DRUID：一个批次 → 结果表 + 逐窗口剖面
python -m druid.cli.reduce_batch ^
    --dir "data\EX2022A" ^
    --out "结果\EX2022A_U-Pb结果.xlsx"

# ② ADEPT：读同一份工作簿里的「剖面窗口」表
Rscript -e "library(ADEPT)
r <- adept('结果/EX2022A_U-Pb结果.xlsx',
            output_path = NA, make_plots = FALSE,
            lower_ablation_time = 0, upper_ablation_time = 1e6,
            smooth = 'none', calibration_uncertainty = 0)
print(r$summary[, c('Analysis','Final age (Ma)','MSWD')])"

ADEPT 会读工作簿里的每一张表，只处理含 Age68 的那张， 其余的表（结果 / 标样QC / 深度剖面域 / 运行参数）会给出警告后跳过。 所以直接把 DRUID 的结果工作簿整个丢给它就行，不需要先拆出那张表。
